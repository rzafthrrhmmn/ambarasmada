# Development Workflow

## 1. Development Environment Setup

```bash
# 1. Clone repository
git clone <repo-url>
cd SisitemPWA

# 2. Install dependencies
composer install
npm install --ignore-scripts

# 3. Configure environment
cp .env.example .env
php artisan key:generate

# 4. Database setup (SQLite for local dev)
touch database/database.sqlite
php artisan migrate

# 5. Start development server
php artisan serve       # Laravel backend
npm run dev             # Vite dev server (HMR)

# 6. Access at http://localhost:8000
```

## 2. Branch Strategy

```
main                  # Production-ready code (deployed to Vercel)
├── develop           # Integration branch (optional)
├── feature/*         # New features (feature/member-import)
├── bugfix/*          # Bug fixes (bugfix/attendance-qr-fix)
└── hotfix/*          # Production hotfixes (hotfix/security-patch)
```

### Creating a Feature Branch
```bash
git checkout -b feature/nama-fitur
# ... development work ...
git add .
git commit -m "feat: deskripsi fitur"
git push origin feature/nama-fitur
```

## 3. Development Cycle

### Standard Feature Development
```
1. Create feature branch
2. Write code (backend + frontend)
3. Run tests: composer test
4. Check formatting: vendor/bin/pint --test
5. Build frontend: npm run build
6. Lint PHP: php -l <files>
7. Commit changes
8. Create Pull Request (if using PR workflow)
9. Deploy to Vercel
```

### Code Change Checklist
Before committing, verify:
- [ ] PHP lint passes (`php -l <file>`)
- [ ] Pint formatting passes (`vendor/bin/pint --test`)
- [ ] Tests pass (`composer test`)
- [ ] Vite build succeeds (`npm run build`)
- [ ] No debug code (console.log, dump(), dd())
- [ ] Rate limiting applied to new mutation routes
- [ ] Role-based middleware applied correctly
- [ ] No secrets/keys in committed code

## 4. Testing Workflow

### Running Tests
```bash
# Run all tests
composer test

# Run only Feature tests
php artisan test --testsuite=Feature

# Run only Unit tests
php artisan test --testsuite=Unit

# Run specific test class
php artisan test --filter=SecurityAuditTest

# Run with coverage (requires Xdebug/Pcov)
php artisan test --coverage
```

### Writing New Tests
```bash
# Generate test file
php artisan make:test Feature/MyFeatureTest

# Or for unit test
php artisan make:test Unit/MyUnitTest --unit
```

### Test Conventions
- Use `RefreshDatabase` trait for database isolation
- Use `DatabaseTransactions` for faster tests (if no migrations needed)
- Mock external services (SMTP, cloud storage)
- Test role-based access control for each endpoint
- Test rate limiting on mutating endpoints

## 5. Build & Deploy

### Pre-Deploy Verification
```bash
# 1. Run all tests
composer test

# 2. Check PHP formatting
vendor/bin/pint --test

# 3. Build frontend for production
npm run build

# 4. Verify no PHP syntax errors
find app/ -name "*.php" -exec php -l {} \;
```

### Deploy to Production (Vercel)
```bash
# Deploy current state to production
npx vercel --prod --force --yes

# Deploy specific branch
git checkout <branch>
npx vercel --prod --force --yes
```

### Post-Deploy Verification
1. Visit https://ambarasmada.vercel.app
2. Login with test credentials
3. Verify new feature works
4. Check error logs: `npx vercel logs`
5. Monitor function execution time

## 6. Git Commit Workflow

### Commit Message Format
```
<type>(<scope>): <subject>

<body>

<footer>
```

**Types:** `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `style`, `perf`
**Scope:** Module name (e.g., `attendance`, `finance`, `layout`)

### Examples
```bash
git commit -m "feat(attendance): add dynamic QR code auto-refresh"
git commit -m "fix(finance): correct transaction reversal logic"
git commit -m "refactor(members): optimize member query performance"
git commit -m "chore(deploy): update .vercelignore to exclude PMTiles"
```

### What to Commit
- Source code changes (PHP, Vue, CSS, JS)
- Route changes
- Migration files
- Documentation (PRD, README, etc.)
- Test files

### What NOT to Commit
- `.env` file
- `vendor/` directory
- `node_modules/`
- `public/build/` (generated by Vercel)
- `.kilo/` directory
- `storage/` (except `.gitignore`)
- `*.log` files
- IDE/editor config files

## 8. Common Development Patterns

### Adding a New Module
```bash
# 1. Create model + migration
php artisan make:model ModuleName -m

# 2. Create controller
php artisan make:controller ModuleNameController --resource

# 3. Add route in routes/web.php
Route::resource('module-name', ModuleNameController::class)
    ->middleware(['auth', 'approved', 'role:Admin,Pembina,Pengurus']);

# 4. Create Inertia pages
#    resources/js/Pages/ModuleName/{Index,Show,Create,Edit}.vue

# 5. Write tests
php artisan make:test Feature/ModuleNameTest

# 6. Update sidebar in AppLayout.vue (add nav item)
```

### Adding a New Field to Existing Model
```bash
# 1. Create migration
php artisan make:migration add_field_to_table --table=table_name

# 2. Update model fillable
# 3. Update frontend form
# 4. Update validation rules
# 5. Write test
# 6. Commit and deploy
```

### Fixing a Bug
```bash
git checkout -b bugfix/issue-description
# Reproduce the bug
# Fix the code
# Add regression test
composer test
git commit -m "fix(scope): description of bug and fix"
npx vercel --prod --force --yes
```

## 9. Emergency Procedures

### Rollback a Deployment
```bash
git revert <commit-hash>
npx vercel --prod --force --yes
```

### Database Rollback
```bash
php artisan migrate:rollback --step=1
php artisan migrate
```

### Clear All Caches
```bash
php artisan optimize:clear
php artisan config:clear
php artisan route:clear
php artisan view:clear
```

### Check Production Logs
```bash
npx vercel logs --follow
```
